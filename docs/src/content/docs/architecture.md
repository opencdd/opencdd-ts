`@opencdd/opencdd` is a TypeScript port of the Ruby
[`opencdd`](https://opencdd.github.io/opencdd-ruby/) gem. The Ruby
gem is the source of truth for semantics — when the gem changes,
this package follows.

## Layered structure

```
@opencdd/opencdd
├── src/
│   ├── models/         Value objects + Database + tree walkers
│   ├── validators/     Runner + R01–R14 rules
│   ├── cddal/          CDDAL format parser/serializer
│   ├── parcel/         Parcel sheet schema (deserialization only)
│   ├── exporters/      Json/Yaml/Mermaid/Csv exporters
│   └── persistence/    Database load/save round-trips
└── tests/              vitest suite
```

### `models/`

Frozen value objects for every CDD entity type — `Klass`, `Property`,
`Unit`, `ValueList`, `ValueTerm`, `Relation`, `ViewControl`,
`ListOfUnit`. All inherit from `Entity`. One in-memory `Database`
holds the entity graph and indexes by IRDI.

Subfolders contain tree walkers (`ClassTree`, `RelationTree`,
`CompositionTree`), the `EffectiveProperties` calculator, the
`Visitor` base class, and supporting types.

### `validators/`

A `Runner` walks the database and applies a list of `Rule`
instances. R01–R14 cover IRDI format, hierarchy acyclicity,
type-specific shape, reference integrity, and well-formedness.
The validators namespace is re-exported as `Validators` to avoid
symbol collisions with the model layer.

### `cddal/`

CDDAL (CDD Algebraic Language) is the canonical plain-text format
for CDD content. This module has a hand-written lexer/parser
(`Parser.ts`), an AST (`AST.ts`), and a serializer (`Builder.ts`).
Round-trip parsing is a core guarantee — every fixture in `tests/`
must round-trip identically.

### `parcel/`

Read-only schema for the Parcel xlsx layout — `Sheet`, `Workbook`,
`WorkbookReader`, `FlatDirReader`. The TS package deserializes
Parcel data but does not write xlsx. xlsx writing is the Ruby gem's
responsibility.

### `exporters/`

Format adapters that walk the `Database` and emit a target format:

- `JsonExporter` — the canonical handoff format between Ruby and TS.
- `YamlExporter` — human-readable persistence.
- `MermaidExporter` — class diagrams for documentation.
- `CsvExporter` — flat property/value tables.

### `persistence/`

`Database.fromJSON` and friends — load and save the full database
as a single JSON document.

## Generated files

`src/models/PropertyIds.generated.ts` and
`src/models/MetaClasses.generated.ts` are GENERATED by the Ruby gem
via the cdd-data submodule. Never hand-edit.

## TypeScript conventions

- **Extensionless imports** (`import { Foo } from "./Foo"`) — ESM
  with `moduleResolution: Bundler`. Consumers must use a bundler.
- **Strict mode** with `noUncheckedIndexedAccess`. Regex match
  groups and array access need `?? fallback` or `!`.
- **Frozen value objects** — model classes call `Object.freeze(this)`
  in their constructors. Mutating model state is a runtime error.

## What this package doesn't do

- **Read xlsx files.** Parcel xlsx reading is Ruby's job. The TS
  package consumes `database.json` produced by the Ruby exporter.
- **Edit content in place.** Value objects are frozen. The Editor
  (forthcoming) will own mutations through a separate layer.
- **Run as a server.** It's a pure library — no I/O, no HTTP.

## Relationship to other repos

- [`opencdd-ruby`](https://github.com/opencdd/opencdd-ruby) —
  canonical Ruby implementation. Produces the `database.json` this
  package consumes.
- [`opencdd.github.io`](https://github.com/opencdd/opencdd.github.io) —
  the OpenCDD Browser. Astro site that consumes this package.
- OpenCDD Editor (forthcoming) — will consume this package for its
  model layer.

See the browser repository README for the full picture.
